# Agent Setup의 철학

[README](README.ko.md) | [English](PHILOSOPHY.md) | **한국어**

확률적 분포와 비용 제약에 집중한 최소주의 AI 워크플로우를 지향합니다.

## AI 코딩은 본질적으로 코더쪽이 하우스인 카지노입니다

> 여기서의 본질은 도박이 아니라, 통계적 기댓값(Positive Expectation)을 의미합니다.

AI 코딩 워크플로우는 결정론적 프로그램이 아니라, 큰 수의 법칙에서 유리한 결과(House Edge)를 얻도록
확률 종형곡선(Bell Curve)을 조정하는 힌트입니다. `SKILL.md`와 `AGENTS.md`는 이 확률 분포를 관리하기 위해 작동합니다.

- **단일 대규모 실행보다 소규모 다중 실행을 지향합니다.**
  큰 판돈(대량 토큰 / 넓은 범위)의 단일 실행보다 작은 판돈의 다중 실행이 유리한 결과를 반복 확보하기에
  적합합니다. 단순 반복이 아닌, 작은 단위 실행으로 유리한 분포를 안정화하는 것이 핵심입니다.
- **과정에 구체적인 분기나 과도한 절차를 강제하지 않습니다.**
  특정 상황에 과적합된 절차는 물병 방향같은 불필요한 의식(ritual)으로 전락합니다. 블랙잭 딜러가 카드 분배와 판돈 회수에 집중하듯,
  본질적인 절차만 최소한으로 안내합니다.
- **Few-Shot을 지양합니다.**
  고정된 예시는 맥락 변화 시 부적합하거나 잘못된 베팅 전략으로 과적합되기 쉽습니다.
- **하우스 엣지를 현실화하려면 판돈 정산이 즉각적이어야 합니다.**
  수동 코드 리뷰는 검증 비용이 큽니다. 반면 엄격한 타입체커(`tsc`, `rustc`)와 단위 테스트는 즉각 패를 접거나(Fold)
  판돈을 회수하는 결정론적 정산기 역할을 합니다. 정산 속도가 빠를수록 단위 시간당 시행 횟수를 늘려 대수의 법칙을 온전히 활용할 수 있습니다.

## 결국 모든 것은 자원의 제약과 현실의 한계에 의해 결정됩니다

확률적 AI의 특성(컨텍스트 윈도우 크기, 어텐션 감쇠)과 사람의 인지 부하를 무시한 거대 프레임워크는 비용으로 작용합니다.
Agent Setup은 모든 예외를 통제하려 하지 않고, 최소한의 불변식(Invariants)만 전달합니다.

- **어텐션과 컨텍스트 윈도우를 메타 지침으로 낭비하지 않습니다.**
  도구 매뉴얼이나 다단계 서브에이전트 로그 대신, 실제 소스 코드와 에러 로그에 모델의 어텐션을 집중시킵니다.
- **도메인 규칙은 최소한의 불변식으로만 규정합니다.**
  복잡한 상태 머신 대신 깨지지 않아야 할 최소한의 핵심 제약만 남겨 모델의 고유 추론(CoT) 역량을 보존합니다.

## Agent Setup의 워크플로우는 더 나은 방식이 나오면 대체할 수 있고 대체되어야 합니다

영구적인 에이전트 문서는 존재하지 않습니다. 변화와 필요에 따라 스킬과 지침을 언제든 교체할 수 있도록 결합도를 낮추고 최소 범위만 규정합니다.

- **모든 에이전트 문서는 약 200줄 이내로 유지하고, 문서 수를 최소화합니다.**
  모듈 간 결합도가 높아지면 수정과 교체가 어려워지고 인지 부하가 가중됩니다. 각 문서는 독립적으로 추가, 수정, 삭제할 수 있어야 합니다.
- **실험은 새로운 스킬 작성으로 검증합니다.**
  실제 필요에 따른 모듈화된 최소 스킬을 검증합니다. 안정화된 스킬은 `AGENTS.md`에 통합하거나 유지하고, 그렇지 않은 스킬은 즉시 폐기합니다.
